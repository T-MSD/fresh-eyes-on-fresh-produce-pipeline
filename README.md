# Fresh Eyes on Fresh Produce — pipeline + API

Sensei challenge, JunctionX Lisbon 2026. For every camera image and every planogram area, predict
`planogram_compliant`, `stock_level` and `stock_value`.

## Setup

With uv:

```bash
brew install uv
uv sync                 # core: pipeline + API
uv sync --extra ml      # adds torch, transformers, open_clip
```

With pip:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Database

Postgres runs in Docker. Credentials come from `.env` (copy `.env.example`).

```bash
docker compose up -d db        # start, data persists in the pgdata volume
docker compose ps              # wait for "healthy"
docker compose exec db psql -U fresh_eyes -d fresh_eyes
docker compose down            # stop; add -v to wipe the data
```

The schema lives in `config/db/schema.py` (SQLAlchemy models, one class per table). Alembic
migrations live in `config/db/migrations/`.

```bash
uv run --env-file .env alembic upgrade head                            # create or update the tables
uv run --env-file .env alembic revision --autogenerate -m "add x"      # after editing schema.py
uv run --env-file .env alembic check                                   # models and DB in sync?
uv run --env-file .env alembic downgrade -1                            # undo the last migration
```

Review every autogenerated migration before applying it.

`uv run --env-file .env pytest` builds a fresh `TEST_DATABASE_URL` database from the migrations
and checks every constraint against it. The name must end in `_test`; pytest drops and recreates
it on each run. Without `TEST_DATABASE_URL` the database tests are skipped.

```
datasets ──< cameras ──< areas >── products >── datasets
   │            │          ▲          ▲ detected_product_id
   │            └──< frames│          │
   │                   │   │          │
   └──< runs ──< predictions ─────────┘     unique (run_id, frame_id, area_id)
                     │
                     └──< tasks             opened and closed frame (NULL while open)
```

Every load of a dataset adds a row to `datasets` (planogram path, images folder, load time) with
its own cameras, products, areas and frames. Nothing is replaced, so earlier runs keep their
predictions. The active dataset is the most recent load.

Every table has an integer `id` primary key generated by the database. Cameras, products and
areas keep the planogram id (`6215`, `11908`, `6215_2`) in `external_id`, unique within one
dataset: a judge planogram can reuse the same ids in a later load. Generated ids stay inside the database;
everything outside it uses `external_id`.

Every timestamp is a `timestamptz` column of type `UTCDateTime`, so every query reads it back in
UTC, whatever the session time zone.

Composite foreign keys keep each row inside one dataset: an area's camera and product, and a
prediction's run, camera and detected product, all belong to the same dataset.

A task is one problem on one area in one run: `restock` (empty), `move_product` (wrong product)
or `top_up` (half). It opens on the frame where the problem appears and closes on the first later
frame where it is gone; its kind never changes. `done_at` is the time staff marked it done. Both
frames reference the run's prediction for the area, so deleting a run deletes its tasks.
`(run_id, area_id, kind, opened_frame_id)` is unique, and an area has at most one open task per
run.

## Loading a dataset

`load` adds a planogram and its images folder (`<camera>/<unix_ts>.jpg`) as a new dataset. Each
path comes from its argument, else from `PLANOGRAM_PATH` / `IMAGES_DIR` in `.env`.

```bash
uv run --env-file .env python cli.py load                                  # paths from .env
uv run --env-file .env python cli.py load path/to/planogram.json path/to/images
uv run --env-file .env python cli.py load --dry-run                        # check only
```

Both inputs are parsed and checked before the database is touched; any problem stops the load.
The insert runs in one transaction, so a failed load leaves no partial dataset. Earlier loads,
their runs and their predictions are never touched. A camera folder missing from the planogram
stops the load; files that are not timestamped JPEGs are listed and skipped.

An image is unreadable when its JPEG header is missing or broken, declares a size of zero or
above `MAX_FRAME_PIXELS` (checked before decoding, so a bad header cannot allocate gigabytes), or
does not decode to the size it declares. EXIF rotation may swap width and height; the stored size
is the decoded one, the image the planogram corners refer to. Unreadable images are listed and
stored without a size, so their areas still get a fallback.

## API

```bash
uv run --env-file .env uvicorn src.main:app --reload
```

`GET /hour-range` returns the earliest and latest frame timestamps with predictions in the
most recent completed run. All API record queries must use `config.db.queries.latest_run()`
to scope records to the newest completed run by `started_at`, breaking ties by the highest `id`.
Only completed (`done`) runs are selected; an empty newest completed run never falls back to
an older run. Newer `running` or `failed` runs are skipped.

```json
{
  "start": "2025-06-27T08:00:00Z",
  "end": "2025-06-27T20:00:00Z"
}
```

The bounds are full frame timestamps normalized to UTC (`Z`), regardless of the database session
timezone. For a run without predictions,
`start` and `end` are `null`. With no completed runs, the endpoint returns `404` with
`{"detail": "No completed runs available"}`. Interactive API documentation is at `/docs`.

`GET /tasks` returns the tasks of the most recent completed run that staff have not marked done.
It uses the same `latest_run()` selection as `/hour-range`; a newest completed run without
pending tasks never falls back to an older run.

```json
{
  "tasks": [{
    "camera": "6215", "area_id": "6215_2", "product_id": "11908",
    "product_name": "BANANA CAT I CNT KG", "kind": "top_up",
    "opened": { "filename": "1751052241.jpg", "ts": "2025-06-27T19:24:01Z" },
    "closed": { "filename": "1751055841.jpg", "ts": "2025-06-27T20:24:01Z" }
  }]
}
```

Tasks are sorted by priority (`restock`, `move_product`, `top_up`), then by opening time,
camera and area, with creation order breaking any remaining tie. No database id is returned.
Closed tasks are included with their closing frame, so the time slider can tell which were
still open at any moment; `closed` is `null` while a task is open. With no completed runs,
the endpoint returns `404` with `{"detail": "No completed runs available"}`. Interactive API
documentation is at `/docs`.

`POST /tasks/done` marks one task of the most recent completed run as done. The body names the
task with the `area_id`, `kind` and `opened.filename` that `GET /tasks` returns:

```json
{ "area_id": "6215_2", "kind": "top_up", "opened_filename": "1751052241.jpg" }
```

It sets the task's `done_at` and returns `204` with no body; the task then disappears from
`GET /tasks`. Marking a task already done also returns `204` and keeps its first `done_at`.
With no completed runs, it returns `404` with `{"detail": "No completed runs available"}`; a
task not in that run returns `404` with `{"detail": "Task not found in the latest completed run"}`.
An invalid body or unknown `kind` returns `422`.

`GET /predictions?at=&camera=` feeds the Store page: the state of every camera at one moment of
the most recent completed run, with the same `latest_run()` selection as `/hour-range`. Each
camera shows the same frame as `GET /cameras/{camera}/frame?at=`: both use `latest_frames()`,
the newest frame at or before `at` (an ISO 8601 time with a time zone; without `at`, the newest
frame) in the run's dataset, with or without predictions, ties resolved to the highest filename.
A camera without a frame by `at` is left out. The optional `camera` keeps only that camera; a
known camera without a frame by `at` returns `{"cameras": []}`, and a camera that is not in the
run's dataset returns `404` with `{"detail": "Camera not found in the latest completed run"}`.

```json
{
  "cameras": [{
    "camera": "6215",
    "frame": { "filename": "1751052241.jpg", "ts": "2025-06-27T19:24:01Z" },
    "areas": [{
      "area_id": "6215_2", "product_id": "11908", "product_name": "BANANA CAT I CNT KG",
      "status": "wrong_product",
      "prediction": {
        "planogram_compliant": false, "stock_level": "half", "stock_value": 0.5,
        "detected_product_id": "11909", "detected_product_name": "BANANA CAT I CNT KG",
        "compliance_confidence": 0.71, "stock_confidence": null
      }
    }, {
      "area_id": "6215_3", "product_id": "11908", "product_name": "BANANA CAT I CNT KG",
      "status": "unknown", "prediction": null
    }]
  }]
}
```

Every area of the camera is listed, sorted by area number, so `areas` is the camera's full
planogram. An area without a prediction in that frame and run has `status: unknown` and
`prediction: null`; older frames and runs never fill the gap, so an empty completed run shows
every area as `unknown`. Otherwise `status` is `empty`, else `wrong_product` when it is not
compliant, else `half`, else `ok`. Cameras are sorted most urgent first: more `empty` areas,
then more `wrong_product`, then more `half`, then more `unknown`, then camera id, so a camera
without data never looks healthier than one that is fully `ok`. A confidence is `null` when the method gives no estimate. With no completed runs, the
endpoint returns `404` with `{"detail": "No completed runs available"}`.

## Layout

```
cli.py                                  # command line: load
config/
  db/
    connection.py                       # engine from DATABASE_URL
    load.py                             # add a dataset load in one transaction
    schema.py                           # SQLAlchemy models (tables)
    migrations/                         # Alembic env, template and versions
ingest/                                 # parse and check planogram + images, no database
src/                                    # pipeline and API
tests/

dataset/                                # gitignored
  planogram.json
  training/<camera_id>/<unix_ts>.jpg
out/                                    # pipeline outputs (gitignored)
```

## Camera view

```text
GET /cameras
    → latest completed run's dataset → every camera and its planogram areas
GET /cameras/{camera}/frame?at=<ISO 8601 Z>
    → latest completed run → last frame at or before at → areas and predictions
GET /images/{camera}/{filename}
    → latest completed run's dataset → stored JPEG
GET /areas/{area_id}/stock
    → latest completed run → stock history in timestamp order
```

The camera list lets the frontend show every camera, including one with no frame at the
selected time, without knowing camera ids in advance:

```json
{
  "cameras": [{
    "camera": "6215", "camera_name": null,
    "areas": [{
      "area_id": "6215_1", "number": 1, "product_id": "20923",
      "product_name": "BANANA DA MADEIRA CNT KG",
      "corners": { "top_left": [370, 179], "top_right": [633, 171],
                   "bottom_right": [629, 248], "bottom_left": [384, 255] }
    }]
  }]
}
```

Cameras are sorted by camera id and areas by area number. Cameras without frames or areas are
included; a camera without areas has `areas: []`.

The camera response contains `camera`, `camera_name`, `filename`, `ts`, `width`, `height`
and `areas`. Omit `at` for the camera's latest frame. An aware timestamp is required when
`at` is supplied; invalid or naive values return 422. Frame selection uses the selected
run's dataset, including frames without predictions. Dimensions and camera name may be null.

Every area contains `area_id`, `number`, `product_id`, `product_name`, `corners`
(`top_left`, `top_right`, `bottom_right`, `bottom_left`) and `prediction`, or null when
that frame has no prediction for the area in the selected run. Corners retain negative
coordinates. A prediction contains `planogram_compliant`, `detected_product_id`,
`detected_product_name`, `stock_level`, derived `stock_value`, `compliance_confidence`
and `stock_confidence`. Unknown detected products and confidence estimates remain null.

Stock history is a JSON array of `{ts, stock_level, stock_value, stock_confidence}` for
the area's predictions in the selected run. A known area without predictions returns `[]`.
All ids exposed by these endpoints are external ids scoped to the selected run's dataset.
No completed run, unknown camera or area, or no eligible frame returns 404. There is no
fallback to older runs. The image endpoint also returns 404 for a missing file or a path
escaping the dataset image folder. Interactive API documentation is available at `/docs`.
