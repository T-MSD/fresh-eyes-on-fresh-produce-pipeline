# Fresh Eyes on Fresh Produce — pipeline + API

Sensei challenge, JunctionX Lisbon 2026. For every camera image and every planogram area, predict
`planogram_compliant`, `stock_level` and `stock_value`.

## Setup

With uv:

```bash
brew install uv
uv sync                 # core: pipeline + API
uv sync --extra ml      # adds torch, transformers, open_clip
```

With pip:

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Database

Postgres runs in Docker. Credentials come from `.env` (copy `.env.example`).

```bash
docker compose up -d db        # start, data persists in the pgdata volume
docker compose ps              # wait for "healthy"
docker compose exec db psql -U fresh_eyes -d fresh_eyes
docker compose down            # stop; add -v to wipe the data
```

The schema lives in `config/db/schema.py` (SQLAlchemy models, one class per table). Alembic
migrations live in `config/db/migrations/`.

```bash
uv run --env-file .env alembic upgrade head                            # create or update the tables
uv run --env-file .env alembic revision --autogenerate -m "add x"      # after editing schema.py
uv run --env-file .env alembic check                                   # models and DB in sync?
uv run --env-file .env alembic downgrade -1                            # undo the last migration
```

Review every autogenerated migration before applying it.

`uv run --env-file .env pytest` builds a fresh `TEST_DATABASE_URL` database from the migrations
and checks every constraint against it. The name must end in `_test`; pytest drops and recreates
it on each run. Without `TEST_DATABASE_URL` the database tests are skipped.

## API

```bash
uv run --env-file .env uvicorn src.main:app --host 127.0.0.1 --port 8000
```

```text
GET /predictions/{frame_id}/{area_id}/frame
    → most recent run → matching prediction → frame metadata (JSON)
```

Predictions are identified by frame and area within the automatically selected run.
All record endpoints must use the shared `most_recent_run` dependency and scope their
queries to that run. The most recent run is ordered by `started_at` descending, then
`id` descending to break ties, regardless of status. Selection happens on each request.
A missing run or prediction returns HTTP 404; older runs are never used as a fallback.

The response contains `run_id`, `id` (frame ID), `camera_id`, `filename`, `ts`,
`width` and `height`. Dimensions can be `null`. This endpoint returns metadata;
it does not read the frame image. Interactive API documentation is available at `/docs`.
